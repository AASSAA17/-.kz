# ЛЗ 9 Управление потоком проекта Съёмка kz

Подготовлены инструмент доски, политики, расчёт метрик, отчёт с CFD и шаблон ретроспективы. **Два фактических спринта пока не подтверждены.** История переходов от команды не предоставлена; даты коммитов не заменяют даты взятия задачи, ожидания и ревью. Симуляция является отдельным учебным примером и не должна сдаваться как реальная работа команды.

Основание: предоставленные методичка, раздел «ЛЗ 9. Симуляция двух спринтов», и «Лекция 9. Гибкая поставка на практике», слайды 10–18, 28–32, 35–37. В методичке отдельно сказано, что полный набор критериев содержится в тематическом плане курса; сам план и эталон ЛЗ 9 не предоставлены. Соответствие проверено по доступным двум материалам.

## Открытие

После обычного запуска сайта откройте **/team.html** или ссылку «Команда проекта» внизу сайта. Для собранного приложения: `npm run build`, `npm start`, адрес `http://localhost:3001/team.html`. Для разработки: `npm run dev`, адрес `http://localhost:5173/team.html`.

Доска работает в браузере и не требует GitHub API или токена. Методичка допускает ручное ведение дат в таблице, если экспорт Projects недоступен. Это локальная альтернатива, а не созданный GitHub Project: общей синхронизации между участниками нет. Выберите одно устройство, назначьте дежурного по обновлению, ежедневно архивируйте JSON и CSV. На другом устройстве сначала импортируйте последнюю выгрузку. Не работайте одновременно с расходящимися копиями.

## Что готово и чем подтверждается

| Требование | Подготовлено | Что требует действий команды |
| --- | --- | --- |
| Доска, ожидание, вход/выход | 6 столбцов, [политики](process.md), история | Переводить карточки в день события |
| WIP | 4 в разработке, не более 2 на участника; 3 ревью; 2 проверка; 1 срочная активная | Утвердить соглашение, соблюдать на практике |
| DoR и DoD | Политики в документе и на доске; для Done запрашиваются свидетельства | Ревью другим человеком и проверенный стенд нельзя заменить галочкой без факта |
| Цели спринтов | Результат для пользователя, редактируемые периоды и цели | Установить реальные периоды; предложенные 2–6 и 9–13 ноября не являются историей |
| Выгрузка | JSON с историей, CSV с каждой сменой статуса | Сохранить реальные данные за оба спринта |
| Метрики | Throughput, cycle time, среднее, p85, средний WIP, возраст, время по этапам | Наблюдать фактическую работу |
| Закон Литтла и CFD | Общий модуль расчёта и отдельные графики за оба периода | Объяснить реальное узкое место и граничные эффекты |
| Ретроспектива | [Шаблон](retrospective.md), одно предлагаемое действие RETRO-01 | Провести встречу, подтвердить владельца и срок, проверить результат |
| Сравнение | [Учебный отчёт](simulation-report.html), расчёт для фактического JSON | Получить два наблюдения и написать обоснованный вывод |

## Файлы

- `board-template.json`, `actual-transitions-template.csv` — начальный бэклог. Все карточки находятся в backlog, готовность не заявлена.
- `actual-metrics.json` — явное состояние `not_observed`, без вымышленных показателей.
- `simulation.json`, `simulation-transitions.csv` — смоделированные события восьми карточек.
- `simulation-report.html` — самостоятельный HTML с таблицами, двумя CFD, законом Литтла и образцом ретро. Открывается без запуска сайта; можно распечатать браузером.
- [Проверка сайта](verification.md) — изменения, автоматические проверки и оставшиеся ограничения.

## Расчёт

Все события содержат часовой пояс. Рабочий календарь — понедельник–пятница, 09:00–17:00, UTC+05, без отдельного праздничного календаря. 8 часов = 1 рабочий день. При другом графике команды надо изменить календарь в `public/flow-core.mjs` и пересчитать оба периода одинаково.

Throughput определяется датой Done в полуоткрытом интервале [start, end), по всей доске, включая переносы. Cycle time завершённой карточки — от первого doing до done. p85 — линейная интерполяция, как PERCENTILE.INC. Средний WIP — интеграл числа активных карточек, делённый на рабочую длительность периода. Он включает doing, review и testing. Время по статусам суммирует все посещения этапа; возвраты не теряются. У незавершённых карточек рассчитывается возраст. Дневные CFD показывают состояния перед концом рабочего дня.

Проверка Литтла: средний WIP сопоставляется с `(throughput / рабочие дни) × средний цикл`. На коротком периоде переносы и незавершённые задачи меняют остаток; расхождение не является автоматическим доказательством неверных дат.

Из корня репозитория:

```sh
npm run lab9
npm run lab9 -- /absolute/path/semka-actual.json /absolute/path/actual-report.html
npm test
```

Первая команда пересоздаёт учебные файлы и шаблоны репозитория, **не историю localStorage**. Для реального отчёта используйте второй вариант: сохранённый JSON с `kind: actual`. JSON — канонический формат импорта. CSV предназначен для Calc/Excel и ручного аудита переходов; обратного импорта CSV нет. При импорте JSON предыдущая версия предлагается браузером как резервная загрузка. При запрете загрузок сначала вручную сохраните JSON.

## Сценарий показа за пять минут

Материалы, код и учебный набор подготовлены с помощью ИИ. Автоматические расчёты и пользовательские сценарии проверены, но факты участия команды, независимого ревью, заказчика и двух спринтов ИИ не подтверждает. Перед сдачей команда проверяет текст и раскрывает использование ИИ по правилам вуза.

1. Открыть `/team.html`, показать фактический бэклог и политику каждого этапа.
2. Открыть «Учебный пример» и указать маркировку симуляции. Показать сравнение: throughput 4/4, ожидание ревью 2/0,5 дня. Остальные времена сохранены одинаковыми.
3. Показать CFD: в первом спринте расширяется полоса ревью. Показать одно действие RETRO-01 и его метрику.
4. Показать скачивание JSON, CSV, HTML и возвращение к рабочей доске.
5. Показать пользовательский вертикальный срез: гостевое бронирование, личная ссылка, административная обработка; локально — регистрация с явно демонстрационным кодом, вход и собственные заявки.

Для фактической сдачи заменить пункт 2 реальными выгрузками после двух спринтов. Наличие работающего инструмента не подтверждает проведённые спринты или независимое ревью.
