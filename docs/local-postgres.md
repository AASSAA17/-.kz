# Локальная PostgreSQL для Съёмка.kz

Приложение подключено к `semka_kz` на `127.0.0.1:5432` под отдельной ролью `semka_app`. Строка подключения хранится в игнорируемом `.env`.

При переносе из SQLite сохранены 6 заявок, 6 ключей идемпотентности, 1 блокировка, 2 административные сессии и 11 записей аудита. Исходная SQLite и её согласованная резервная копия остаются в `data/`. Остальные таблицы на момент переноса пустые.

В pgAdmin: PostgreSQL 18 → Databases → semka_kz → Schemas → public → Tables. Для показа без контактов используйте `docs/postgres-demo.sql` в Query Tool.

Таблицы: bookings — заявки; blocks — заблокированное время; idempotency — защита от повторной отправки; audit — история изменений заявок; sessions — административные сессии; login_attempts — ограничения входа администратора; users — аккаунты; user_sessions — пользовательские сессии; auth_rate_limits — ограничения пользовательской авторизации; phone_verifications — метаданные подтверждений; audit_events — события аккаунтов.

Каталог локаций пока хранится в `server/locations.mjs`, отдельной таблицы локаций нет.

Для проверки PostgreSQL тесты выполнены в отдельной базе `semka_test` и временной схеме. Все 7 проверок прошли: конкурентная бронь, идемпотентность, гонки бронирований и блокировок, сохранность после переподключения, освобождение просроченных слотов.

Повторный перенос выполняется скриптом `scripts/migrate-sqlite-postgres.mjs` только при остановленном API и пустой целевой базе. Скрипт отменяет перенос, если целевые таблицы уже содержат данные. Обычно повторный перенос не нужен.
