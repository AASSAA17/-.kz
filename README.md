# Съёмка.kz — локальный MVP

Сервис выбора и бронирования съёмочных локаций в Астане. Клиент выбирает площадку, дату и свободное время, оставляет заявку; администратор управляет заявками. Интерфейс и API запускаются на компьютере, заявки сохраняются в SQLite.

## Быстрый запуск

Нужен **Node.js 24 или новее** с npm. Проверьте версии:

```sh
node --version
npm --version
```

В терминале в папке репозитория выполните:

```sh
npm install
npm run setup
npm run dev
```

Откройте **http://localhost:5173**. Команда `dev` одновременно запускает Vite и API. Остановить оба процесса можно через `Ctrl+C` в том же терминале. Отдельные окна терминала не открываются.

Для установки точно зафиксированных в `package-lock.json` версий можно использовать `npm ci` вместо `npm install`. После установки зависимости работают локально; постоянное подключение к интернету приложению не требуется.

`npm run setup` создаёт `.env` со случайным паролем администратора и показывает его в терминале. Если `.env` уже существует, команда оставляет его без изменений. Чтобы посмотреть пароль позже, откройте `.env`: значение находится после `ADMIN_PASSWORD=`. Не отправляйте этот файл и пароль в репозиторий или переписку.

В Windows PowerShell, если запуск `npm.ps1` запрещён политикой компьютера, используйте `npm.cmd` вместо `npm`; менять политику PowerShell не требуется.

## Что работает

- Каталог пяти демонстрационных площадок: лофт, циклорама, крыша, зимний сад и ангар.
- Выбор площадки, даты и времени; расчёт стоимости по длительности аренды.
- Создание заявки и проверка пересечения бронирований на сервере.
- Ссылка для проверки статуса заявки без регистрации.
- Просмотр заявок, изменение статусов и блокировка времени через административную страницу.
- Сохранение данных после перезапуска сервера.

Названия, описания, цены, доступность и другие данные каталога подготовлены для демонстрации. Они не подтверждают реальные условия аренды или существование доступного для заказа предложения.

Источники иллюстраций и условия их использования указаны в [списке фотографий](docs/image-credits.md).

Подбор фотографа или съёмочной команды, пакетные скидки, индивидуальный поиск площадки, платежи, SMS и внешние уведомления в этот MVP не входят. Первоначальная идея проекта сохраняется в [описании границ MVP](docs/mvp-scope.md).

## Администратор и бронирование

Откройте **http://localhost:5173/admin** и введите пароль из `.env`. Отдельное имя пользователя не требуется. Для демонстрации используйте вымышленные контактные данные. После работы завершите административную сессию через кнопку выхода.

Время аренды — с 09:00 до 21:00 по Астане, с шагом один час. Можно выбрать длительность от одного до восьми часов и дату в пределах ближайших 90 дней. Заявка сначала получает статус ожидания и временно занимает интервал на два рабочих часа в рамках 09:00–21:00. Администратор подтверждает, отклоняет или отменяет её. Неподтверждённая заявка истекает по окончании этого срока. Оплата в приложении не принимается.

## Локальная сборка без Vite

```sh
npm run build
npm start
```

Откройте **http://localhost:3001**. API отдаёт собранный интерфейс из `dist/`. Перед `npm start` остановите `npm run dev`, чтобы освободить порт 3001. Это локальный режим проверки собранного приложения, а не настройка публичного сервера.

## Настройки и данные

| Настройка | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3001` | Порт API и собранного сайта |
| `ADMIN_PASSWORD` | Генерируется при `setup` | Пароль администратора, от 12 до 256 символов |
| `DB_PATH` | `data/semka.sqlite` | Необязательный путь к базе SQLite |

Сервер слушает `127.0.0.1`. Для первого запуска оставьте порты по умолчанию: 5173 для Vite, 3001 для API. Если меняете порт API, обновите также адрес прокси `/api` в `vite.config.js`. Настройки перечислены в [.env.example](.env.example); копировать пример вместо `npm run setup` не нужно.

База и служебные файлы SQLite создаются в `data/`. Они, `.env`, зависимости и сборка исключены из Git. Не удаляйте `data/`, если хотите сохранить заявки.

Для резервной копии остановите приложение и скопируйте **всю папку `data/`** в безопасное место. Пароль при необходимости сохраните отдельно. Для восстановления при остановленном приложении верните сохранённую папку `data/`. Копирование только одного файла работающей SQLite может пропустить данные из журнала WAL.

## Проверка

```sh
npm test
npm run build
```

API-тесты создают изолированные тестовые базы и не требуют вашего `.env`. Workflow [Test and build](.github/workflows/ci.yml) повторяет `npm ci`, `npm test` и `npm run build` на Node.js 24 в Ubuntu и Windows при push и pull request. Результат конкретного запуска смотрите во вкладке Actions репозитория.

Пошаговый сценарий демонстрации, включая повторное бронирование занятого времени и перезапуск сервера, приведён в [проверке MVP](docs/manual-smoke-test.md). Архитектура, API и ограничения описаны в [технической заметке](docs/mvp-architecture.md).

## Технологии

| Слой | Реализация MVP |
| --- | --- |
| Интерфейс | React, Vite |
| API | Node.js 24, `node:http` |
| Хранение | SQLite, встроенный модуль `node:sqlite` |
| Запуск | npm, локальные Node.js-процессы |

Отдельный сервер базы данных, Docker, облачный аккаунт и внешний API для работы MVP не нужны. PostgreSQL и инфраструктура из первоначального плана могут быть добавлены при развитии проекта.

## Границы применения

MVP предназначен для локального запуска, проверки сценариев и учебной демонстрации. Перед публикацией в интернете понадобятся отдельная настройка HTTPS, проверка защиты и нагрузки, управление пользователями и правами, резервное копирование, мониторинг и согласованные правила работы с персональными данными. Подробности и незакрытые ограничения перечислены в технической заметке.
